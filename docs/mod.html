Modulation

Envelopes, function generators, clocks, chaos and controlled randomness, from Peaks, Tides, Streams and Marbles.

These produce control signals. Outputs are 0..1 (unipolar) or ±1 (bipolar), as each section says. Multiply by 10 V or 5 V for Rack.

Envelope

#include "pt/mod/envelope.h" · from Peaks

A multi-segment envelope with ADSR, AD, AR and looping presets, or fully custom segments with their own levels, times and curves.

How it works. Segment i ramps from level i to level i+1 over its time, along a curve: linear, exponential (fast then slow) or quartic (slow then fast).

  • Retrigger: a rising gate restarts from the current level, so there's no click (or from 0, with hard reset).
  • Sustain: the envelope holds at the sustain point while the gate is high, and a falling gate jumps to it.
  • Loop: a loop cycles through segments, like an LFO with any shape.
CallEffect
setAdsr(a, d, s, r)Times in seconds, sustain 0..1. Quartic attack, exponential decay and release (Peaks' choice).
setAd(a, d), setAr(a, r), setAdr(a, d, s, r)AD ignores the gate length; AR holds at the top while the gate is high.
setAdLoop(a, d), setAdrLoop(a, d, s, r)Looping versions: they cycle while running.
setLevel(i, x), setTime(i, s), setShape(i, shape)Custom segments: Envelope::LINEAR, EXPONENTIAL or QUARTIC.
setNumSegments(n), setSustainPoint(i), setLoop(start, end)Up to 6 segments; sustain point 0 means none; loop end 0 means no loop.
setHardReset(on)Every trigger restarts from level 0.
process(gate)Returns 0..1. active() is false once it has finished.
pt::Envelope env;   // onSampleRateChange: env.init(e.sampleRate);

// ADSR with knobs mapped to useful time ranges
auto time = [](float k) { return 0.001f * std::pow(5000.f, k); };   // 1 ms to 5 s
env.setAdsr(time(params[A].getValue()), time(params[D].getValue()),
            params[S].getValue(), time(params[R].getValue()));
bool gate = inputs[GATE].getVoltage() >= 1.f;
outputs[ENV].setVoltage(10.f * env.process(gate));
// A custom 4-segment envelope: pluck, dip, swell, release
env.setNumSegments(4);
env.setLevel(0, 0.f);  env.setLevel(1, 1.f);  env.setLevel(2, 0.3f);
env.setLevel(3, 0.8f); env.setLevel(4, 0.f);
env.setTime(0, 0.005f); env.setShape(0, pt::Envelope::LINEAR);
env.setTime(1, 0.2f);   env.setShape(1, pt::Envelope::EXPONENTIAL);
env.setTime(2, 1.0f);   env.setShape(2, pt::Envelope::QUARTIC);
env.setTime(3, 0.5f);   env.setShape(3, pt::Envelope::EXPONENTIAL);
env.setSustainPoint(3);   // hold the swell's peak while the gate is high
env.setLoop(0, 0);

Slope

#include "pt/mod/slope.h" · from Tides (2018)

A function generator: the single-channel core of Tides. It is an envelope, a looping LFO or an audio oscillator, with a skewable and shapeable waveform and end-of-attack and end-of-release gates.

How it works.

  1. A ramp runs at the set frequency: once per trigger (AD), continuously (LOOPING), or up while the gate is held and down when released (AR).
  2. slope splits it into a rise and a fall of different lengths.
  3. shape bends both through a family of curves: logarithmic, sine, linear, exponential.
  4. smoothness below 0.5 low-passes the result; above 0.5 it wavefolds it.
  5. In the AUDIO range the looping waveform is anti-aliased.

Tides' four-output modes aren't included; build them from several Slopes.

CallEffect
setMode(m)Slope::AD, LOOPING or AR.
setRange(r)Slope::CONTROL (envelopes and LFOs) or AUDIO (anti-aliased oscillator, looping only).
setFrequency(hz)Cycle rate; in AD, one rise plus fall lasts 1/hz.
setSlope(x)0: instant rise, slow fall. 0.5: symmetric. 1: slow rise, instant fall.
setShape(x)Curve family; 0.5 is roughly linear.
setSmoothness(x)Below 0.5 smoother, above 0.5 folded.
process(gate)Returns 0..1 (AD, AR) or ±1 (LOOPING). The gate triggers AD, holds AR, and resets LOOPING.
endOfAttack(), endOfRelease()Gates for chaining and clocking.
// Tides-style function generator: mode switch, four knobs, EOA/EOR gates
pt::Slope slope;   // onSampleRateChange: slope.init(e.sampleRate);

slope.setMode(static_cast<pt::Slope::Mode>(int(params[MODE].getValue())));
slope.setFrequency(0.1f * std::pow(1000.f, params[FREQ].getValue()));   // 0.1 to 100 Hz
slope.setSlope(params[SLOPE].getValue());
slope.setShape(params[SHAPE].getValue());
slope.setSmoothness(params[SMOOTH].getValue());
float v = slope.process(inputs[TRIG].getVoltage() >= 1.f);
bool looping = int(params[MODE].getValue()) == pt::Slope::LOOPING;
outputs[OUT].setVoltage(looping ? 5.f * v : 8.f * v);   // Tides' levels: ±5 V or 0..8 V
outputs[EOA].setVoltage(slope.endOfAttack() ? 10.f : 0.f);
outputs[EOR].setVoltage(slope.endOfRelease() ? 10.f : 0.f);
// As an audio oscillator
osc.setMode(pt::Slope::LOOPING);
osc.setRange(pt::Slope::AUDIO);
osc.setFrequency(pt::voltToHz(inputs[VOCT].getVoltage()));
outputs[AUDIO].setVoltage(5.f * osc.process(false));

ClockToRamp

#include "pt/mod/clock_to_ramp.h" · from Tides (2018)

Turns a clock into a smooth phase ramp (0..1 per period), optionally multiplied or divided. It is how Tides and Marbles lock to an external clock. Use the ramp to drive anything that must stay in time: a Slope, a Lag, a wavetable, a sequencer's step position.

How it works.

  • Each clock period is measured and the next one predicted. The predictor compares "same as last time" with "same as N pulses ago" (N up to 8) and uses whichever has been most accurate, so swung and patterned clocks are followed too.
  • The ramp runs at the predicted speed and is corrected at each pulse.
  • With a steady pulse width, the falling edge serves as an extra timing point.
  • After about 3 s without a pulse it starts again.
CallEffect
init(sampleRate, maxHz = 40)Clocks above maxHz are followed directly, without prediction.
setRatio(multiply, divide)Output rate = clock × multiply / divide; it realigns every divide pulses.
process(clock)The clock as a gate. Returns the ramp.
frequency(), reset()The output rate in Hz; start over.
// A clock-synced LFO: ramp into a sine, x2 or /2 by switch
pt::ClockToRamp clock;   // onSampleRateChange: clock.init(e.sampleRate);

int mode = int(params[RATIO].getValue());   // 0: /2, 1: x1, 2: x2
clock.setRatio(mode == 2 ? 2 : 1, mode == 0 ? 2 : 1);
float ramp = clock.process(inputs[CLOCK].getVoltage() >= 1.f);
outputs[RAMP].setVoltage(10.f * ramp);
outputs[SINE].setVoltage(5.f * pt::sineFromPhase(ramp));

BouncingBall

#include "pt/mod/bouncing_ball.h" · from Peaks

An envelope that falls like a dropped ball, bouncing lower and faster until it comes to rest. Use it for accelerating ratchets, bouncing modulation, or a lively decaying envelope.

How it works. A small physics simulation, one step per sample. Gravity changes the velocity, the velocity moves the position, and at the floor the velocity reverses, multiplied by the elasticity. Peaks used fixed point; this port works in seconds.

CallEffect
setGravity(x)0..1. How fast it falls: from about 0.4 s to fall the full height, up to audio-rate buzzing.
setBounce(x)0..1. Elasticity: 0 stops dead, 1 bounces almost forever.
setHeight(x), setVelocity(x)Drop height 0..1; initial velocity −1..1 (positive throws it up first).
trigger(), process(gate)Drop it; a rising gate also drops it. Returns the height, 0..1.
pt::BouncingBall ball;   // onSampleRateChange: ball.init(e.sampleRate);

ball.setGravity(params[GRAVITY].getValue());
ball.setBounce(params[BOUNCE].getValue());
float h = ball.process(inputs[TRIG].getVoltage() >= 1.f);
outputs[OUT].setVoltage(10.f * h);
// Each impact as a trigger: the ball has just hit the floor
outputs[HITS].setVoltage(h == 0.f && lastHeight > 0.f ? 10.f : 0.f);
lastHeight = h;

Lorenz

#include "pt/mod/lorenz.h" · from Streams

A chaotic modulation source with three smooth, endlessly varying outputs that never quite repeat.

How it works. The Lorenz system describes a point moving through 3D space under three linked equations. With the classic constants it loops round two "wings", switching between them unpredictably: the famous butterfly. Each sample moves the point a small step; the rate sets the step size.

CallEffect
setRate(x)0..1, exponential: from a slow drift up to audio-rate buzz.
process()Advances one sample; returns x().
x(), y(), z()About ±1 each. x and y swing between the wings; z rises and falls with each loop.
pt::Lorenz lorenz;   // onSampleRateChange: lorenz.init(e.sampleRate);

lorenz.setRate(params[RATE].getValue());
lorenz.process();
outputs[X].setVoltage(5.f * lorenz.x());
outputs[Y].setVoltage(5.f * lorenz.y());
outputs[Z].setVoltage(5.f * lorenz.z());

Quantizer

#include "pt/mod/quantizer.h" · from Marbles

Snaps a pitch CV to a scale, with an "amount" control that thins the scale down to its most important notes.

How it works. Each scale degree has a weight from 0 to 255; in C major, C is 255, G 192, E and B 128, and so on. Turning amount up raises a threshold:

  • at 0, nothing is quantised;
  • just above 0, every note is allowed (chromatic);
  • higher, only notes above the threshold remain: the scale, then a pentatonic-like subset, then the triad, then root and fifth, and finally the root alone.

Hysteresis stops the output flickering when the input sits halfway between two notes.

CallEffect
init(scale)A Quantizer::Scale: base interval (1 V = octave), number of degrees, and {voltage, weight} for each.
Quantizer::preset(p)Marbles' presets: MAJOR, MINOR, PENTATONIC, PELOG, RAAG_BHAIRAV, RAAG_SHRI.
process(volts, amount, hysteresis = true)Returns the quantised pitch in volts.
pt::Quantizer quant;
MyModule() { quant.init(pt::Quantizer::preset(pt::Quantizer::MINOR)); }

float amount = params[AMOUNT].getValue();   // 0 = off ... 1 = root only
outputs[OUT].setVoltage(quant.process(inputs[IN].getVoltage(), amount));
// A custom scale: a whole-tone scale, all notes equally important
pt::Quantizer::Scale wholeTone = {1.f, 6, {}};
for (int i = 0; i < 6; ++i) wholeTone.degree[i] = {i * 2.f / 12.f, 200};
quant.init(wholeTone);

HysteresisQuantizer

#include "pt/mod/hysteresis_quantizer.h" · from stmlib

Turns a continuous 0..1 value (a knob or a CV) into one of N steps, without flickering between two steps near a boundary. Use it for mode selectors, octave switches, or choosing from a list by CV.

How it works. To change step, the value has to go a little past the halfway point (by the hysteresis, a fraction of a step), so small noise near a boundary changes nothing.

CallEffect
init(numSteps, hysteresis = 0.25, symmetric = false)Not symmetric: each step gets an equal share of 0..1. Symmetric: step 0 is exactly at 0 and the last step exactly at 1.
process(value)Returns the step, 0..numSteps−1. value() is the latest.
pt::HysteresisQuantizer waveSelect;
MyModule() { waveSelect.init(5); }

// Pick one of 5 waveforms with a knob plus CV, without chattering
int wave = waveSelect.process(pt::clamp(params[WAVE].getValue() + inputs[WAVE_CV].getVoltage() / 10.f, 0.f, 1.f));

Lag

#include "pt/mod/lag.h" · from Marbles

Clock-synchronised glide between stepped values, from sharp steps to smooth glides to S-curves, always in time with the clock. Marbles' "steps" control.

How it works. The glide time follows the clock: a phase ramp (0..1 per step) tells the lag how long a step is, so the same setting sounds proportional at any tempo.

  • Smoothness 0 to 0.6: a low-pass glide, from instant to about half a step.
  • Smoothness 0.6 to 1: a crossfade into interpolation along the step, from an S-curve to linear, so the output traces a smooth path through the values.
CallEffect
init()Resets.
resetRamp()Call at each new step, so interpolation starts from the current output.
process(value, smoothness, phase)The current step's value, smoothness 0..1, and the phase within the step.
// Random steps on a clock, smoothed in time with it
pt::ClockToRamp clock;
pt::Lag lag;
pt::Random rng;
float value = 0.f, previousRamp = 0.f;

float ramp = clock.process(inputs[CLOCK].getVoltage() >= 1.f);
if (ramp < previousRamp) {          // the ramp wrapped: a new step
    value = rng.uniform();
    lag.resetRamp();
}
previousRamp = ramp;
outputs[OUT].setVoltage(10.f * lag.process(value, params[STEPS].getValue(), ramp));

RandomSequence

#include "pt/mod/random_sequence.h" · from Marbles

Random values that can loop: Marbles' "déjà vu".

  • At 0 every value is new.
  • Turning it up makes the sequence repeat a loop of recent values, more and more faithfully.
  • At 0.5 it locks to the loop.
  • Past 0.5 it jumps randomly around inside the loop.

How it works. A loop holds the last length values. At each step a "mutation" happens with probability (2·dejaVu − 1)², which is high at both ends and zero in the middle. Below 0.5, a mutation replaces the loop's next value with a fresh one, so the loop slowly evolves. Above 0.5 it jumps to a random place in the loop. Otherwise the sequence steps through the loop in order. next(input) records outside values instead, which makes it a looping sample-and-hold or shift register.

Not included: Marbles' replay and history features, which belong to the module.

CallEffect
init(seed = 0x21)Fills the loop with random values.
setDejaVu(x), setLength(n)0..1; loop length 1..16 steps.
next(), next(input)The next value, 0..1; or record the input (0..1).
reset()Restart the loop from its first step.
// Marbles-style: a clocked random voltage with deja vu and loop length
pt::RandomSequence seq;
dsp::SchmittTrigger clockTrig;
float held = 0.f;
MyModule() { seq.init(); }

seq.setDejaVu(params[DEJA_VU].getValue());
seq.setLength(1 + int(params[LENGTH].getValue() * 15.f));
if (clockTrig.process(inputs[CLOCK].getVoltage(), 0.1f, 1.f)) held = seq.next();
outputs[OUT].setVoltage(10.f * held - 5.f);
// Looping sample-and-hold: sample the input, then loop what was sampled
if (clockTrig.process(inputs[CLOCK].getVoltage(), 0.1f, 1.f)) {
    float in = pt::clamp(inputs[IN].getVoltage() / 10.f + 0.5f, 0.f, 1.f);
    held = seq.next(in);   // deja vu 0: always records; 0.5: replays the loop
}
