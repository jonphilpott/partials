Core

Small helpers the components are built on, also useful directly in your own modules. They replace the parts of stmlib that Gillet's code relies on.

Every function is a plain inline function in namespace pt. None allocates memory or keeps hidden state, so all are safe to call from process().

math.h

from stmlib dsp/dsp.h

Clamping, table lookup, blending, saturation and smoothing.

#include "pt/core/math.h"

clamp(x, lo, hi)

Returns x kept within [lo, hi]. Rack plugins build as C++11, which has no std::clamp.

// Knob plus CV, kept in the 0..1 range a component expects
float structure = pt::clamp(params[STRUCTURE].getValue()
                            + inputs[STRUCTURE_CV].getVoltage() / 10.f, 0.f, 1.f);

interpolate(table, index, size)

Reads a lookup table at a fractional position, blending the two nearest entries (linear interpolation).

  • index runs from 0 to 1.
  • size is the number of steps, so the table must hold size + 1 entries. The extra guard entry lets the last step blend without wrapping.

Use it for curves that are too costly to compute per sample, or that you designed by hand.

// A hand-drawn response curve in 4 steps (5 points)
static const float curve[5] = {0.f, 0.1f, 0.3f, 0.6f, 1.f};
float shaped = pt::interpolate(curve, params[AMOUNT].getValue(), 4.f);
// AMOUNT = 0.375 sits halfway between curve[1] and curve[2]: returns 0.2

interpolateWrap(table, index, size)

As interpolate(), but only the fractional part of index counts: 1.25 reads the same place as 0.25. Use it for periodic tables such as one cycle of a waveform, driven by a phase that may run past 1.

// A wavetable oscillator from a single-cycle table of 256 steps (257 entries)
phase += hz * args.sampleTime;                 // no need to wrap the phase
float out = pt::interpolateWrap(myWave, phase, 256.f);
phase -= std::floor(phase);                    // keep it small for precision

interpolateHermite(table, index, size)

Cubic interpolation through the four nearest points. It is smoother than linear and adds less high-frequency grit when a table is read slowly or sweeps. It needs one guard entry before the position and two after.

// Table with guard points: data[0] is a guard, data[1..N+1] the curve, data[N+2] a guard
float y = pt::interpolateHermite(data + 1, x, float(N));

To record and play back a sample with it, like Pd's tabwrite~ and tabread4~, see Recording and playing a sample in the toolkit.

crossfade(a, b, fade)

Linear blend: fade = 0 gives a, 1 gives b, 0.5 gives the average.

// Dry/wet mix knob
float mix = params[MIX].getValue();
float out = pt::crossfade(dry, wet, mix);

smoothStep(x)

S-shaped curve on 0..1: slow at both ends, fastest in the middle. Good for crossfades and morphs that shouldn't jump at the edges.

// Equal-feeling morph between two oscillators
float m = pt::smoothStep(params[MORPH].getValue());
float out = pt::crossfade(oscA, oscB, m);

softLimit(x)

Cheap tanh-like saturation: almost linear for small signals, curving to exactly ±1 at x = ±3. Only valid between −3 and 3. Use softClip() if the input can go further.

// Gentle warmth on a signal that stays within ±3
float y = pt::softLimit(1.5f * x);

softClip(x)

softLimit() made safe for any input: values beyond ±3 return ±1. A cheap overdrive, or a guard against a resonant patch blowing up.

// Drive knob from clean (1×) to heavily saturated (10×)
float drive = 1.f + 9.f * params[DRIVE].getValue();
outputs[OUT].setVoltage(5.f * pt::softClip(drive * in));

onePole(state, target, coefficient)

Moves state a fraction coefficient (0..1) of the way to target. Called every sample, this is a one-pole low-pass: exponential smoothing with a time constant of about 1 / (coefficient · sampleRate) seconds. Use it to smooth knobs and CVs and avoid zipper noise. For a filter set in Hz, use OnePole.

float cutoffSmoothed = 0.f;   // member

// in process(): reach the knob value with a ~10 ms time constant
float c = args.sampleTime / 0.010f;
pt::onePole(cutoffSmoothed, params[CUTOFF].getValue(), c);

slope(state, target, rise, fall)

As onePole(), with separate speeds for rising and falling. The classic use is an envelope follower: fast attack, slow release.

float envelope = 0.f;   // member

// Attack ~1 ms, release ~200 ms
float rise = args.sampleTime / 0.001f, fall = args.sampleTime / 0.2f;
pt::slope(envelope, std::fabs(in), rise, fall);
outputs[ENV].setVoltage(10.f * envelope);

slew(state, target, maxDelta)

Moves state towards target by at most maxDelta per call: a fixed-rate slew limiter (linear glide, not exponential). Use it for portamento or to limit how fast a CV can change.

float pitch = 0.f;   // member, in volts

// Glide at most 2 octaves per second
pt::slew(pitch, inputs[VOCT].getVoltage(), 2.f * args.sampleTime);
float hz = pt::voltToHz(pitch);

rescaleCoefficient(c, ratio)

Converts a per-sample one-pole coefficient tuned at one sample rate to another, so the smoothing time in seconds stays the same. ratio is originalRate / newRate. Useful when porting code written for a fixed rate, as Gillet's was.

How it works: after n samples a one-pole covers 1 − (1 − c)n of the distance to its target, so (1 − c) is raised to the power ratio.

// Code written for 32 kHz used c = 0.01 per sample.
// The same smoothing time at the current rate:
float c = pt::rescaleCoefficient(0.01f, 32000.f / args.sampleRate);
pt::onePole(state, target, c);

units.h

from stmlib dsp/units.h

Conversions between pitch voltages, notes, intervals and Hz. The library works in Hz; these bridge to Rack's 1 V/octave standard, where 0 V is C4 = 261.6256 Hz (available as pt::kFreqC4).

#include "pt/core/units.h"

voltToHz(volts)

Rack pitch voltage to Hz. Every volt doubles the frequency: 0 V = 261.63 Hz, 1 V = 523.25 Hz, −1 V = 130.81 Hz.

// Pitch knob (±4 octaves) plus V/Oct input
float volts = params[PITCH].getValue() + inputs[VOCT].getVoltage();
resonator.setFrequency(pt::voltToHz(volts));

hzToVolt(hz)

Hz to Rack pitch voltage, the inverse of voltToHz(). Use it to output a pitch CV you have computed in Hz, for example from a pitch tracker.

float detectedHz = 440.f;
outputs[PITCH_OUT].setVoltage(pt::hzToVolt(detectedHz));   // 0.75 V

semitonesToRatio(semitones)

Interval to frequency ratio: 12 semitones = 2.0, 7 (a fifth) ≈ 1.498, −12 = 0.5. Fractional semitones work, for detune in cents.

// Second voice a fifth up, with a fine-tune knob of ±50 cents
float ratio = pt::semitonesToRatio(7.f + params[FINE].getValue() * 0.5f);
voice2.setFrequency(hz * ratio);

midiToHz(note)

MIDI note number to Hz: note 69 = A4 = 440 Hz, note 60 = middle C = 261.63 Hz.

// A fixed bass note, E1 (MIDI 28)
string.setFrequency(pt::midiToHz(28.f));   // 41.2 Hz

random.h · Random

from stmlib utils/random.h

A tiny, fast pseudo-random generator. Each component owns its own, so seeding one never affects another, and a seeded generator repeats the same sequence, which is useful for tests and repeatable patterns.

MethodReturns
seed(s)Restarts the sequence from s.
word()Raw 32-bit integer.
uniform()Float in [0, 1).
bipolar()Float in [−1, 1): white noise.
#include "pt/core/random.h"

pt::Random rng;   // member

// White noise output
outputs[NOISE].setVoltage(5.f * rng.bipolar());

// Random gate: on a clock, open with 30% probability
if (clock.process(inputs[CLOCK].getVoltage()))
    gateOpen = rng.uniform() < 0.3f;

// Random choice of one of 8 steps
int step = rng.word() % 8;

tables.h

replaces the pre-computed tables in the firmware's resources.cc

The firmware ships these tables pre-computed. Here each is built the first time it is used, and is then shared by every module instance. Components build the tables they need in init(), so the audio thread never pays for it. If you use a table directly, call it once in your module's constructor for the same reason.

#include "pt/core/tables.h"

sineTable()

One sine cycle in pt::kSineTableSize (512) steps, plus a quarter cycle and a guard point. Cosine is the same table read a quarter cycle (128 entries) later. Read it with interpolateWrap() for a cheap sine oscillator or LFO.

MyModule() { pt::sineTable(); }   // build it outside the audio thread

// in process(): a sine LFO and its quadrature (90° later) partner
lfoPhase += rate * args.sampleTime;
lfoPhase -= std::floor(lfoPhase);
float s = pt::interpolateWrap(pt::sineTable(), lfoPhase, pt::kSineTableSize);
float c = pt::interpolateWrap(pt::sineTable(), lfoPhase + 0.25f, pt::kSineTableSize);

lut4Decades()

The curve 104x for x = 0..1: four decades (1 to 10,000) in 256 steps. It maps a knob onto a range wide enough for decay times or Q. The modal resonator uses it for damping.

// Map a knob to a time between 1 ms and 10 s
float k = params[TIME].getValue();
float seconds = 0.001f * pt::interpolate(pt::lut4Decades(), k, 256.f);

lutStiffness()

The modal resonator's structure curve: how much each partial is stretched away from a harmonic series, for structure 0..1. It is negative (bell-like) below 0.25, zero (a string) from 0.25 to 0.3, then rises steeply (bars, plates, metal). Useful for building your own additive or modal instrument with the same feel.

// Partial frequencies for an additive voice with Rings' inharmonicity
float stiffness = pt::interpolate(pt::lutStiffness(), structure, 256.f);
float stretch = 1.f, partialHz = hz;
for (int k = 0; k < 16; ++k) {
    partials[k] = partialHz * stretch;
    stretch += stiffness;
    stiffness *= stiffness < 0.f ? 0.93f : 0.98f;
    partialHz += hz;
}

lutSvfShift()

Phase delay, in periods, that an Svf low-pass adds to a note, indexed by the cutoff in semitones above the note (0..256, read with size 1). The String subtracts it from its delay line so its damping filter doesn't pull the note flat. Do the same in any tuned feedback loop with a low-pass inside.

// Feedback comb tuned to hz, with a low-pass 36 semitones above it in the loop
float period = args.sampleRate / hz;
float shift = pt::interpolate(pt::lutSvfShift(), 36.f, 1.f);   // in periods
float delay = period * (1.f - shift);
