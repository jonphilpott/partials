mutablelib

Emilie Gillet's Mutable Instruments DSP, taken apart into small building blocks for VCV Rack modules.

Think of it as a lego set for new modules. Each component is one header containing one class: a resonator, a string, a reverb, a drum voice. It is not a way to rebuild Mutable modules: Rings, Clouds and Plaits already exist in Rack, and things Rack already does well, such as plain saw oscillators, are left out.

Using it in a Rack plugin

New to building Rack plugins? Getting started covers installing the tools and Rack SDK and building the example modules. Then the tutorial walks through building a module from scratch: a sawtooth oscillator into a low-pass filter.

The library is header-only. Point your plugin's Makefile at it:

FLAGS += -I../mutablelib/include

Then include what you need. Every component follows the same pattern:

#include "ml/filter/svf.h"

struct MyModule : Module {
    ml::Svf filter;                          // plain member, no allocation

    void onSampleRateChange(const SampleRateChangeEvent& e) override {
        filter.init(e.sampleRate);           // call before first process()
    }

    void process(const ProcessArgs& args) override {
        filter.setFrequency(ml::voltToHz(inputs[CUTOFF].getVoltage()), 0.707f);
        float in = inputs[IN].getVoltage() / 5.f;   // Rack ±5 V → ±1
        outputs[OUT].setVoltage(5.f * filter.process(in).lp);
    }
};

onSampleRateChange also runs when the module is added, so init() there is enough.

For quick experiments, #include "ml/ml.h" pulls in every component. In a finished module, include only what you use: compile times are shorter.

Six complete example modules are in examples/rack-plugin; see Getting started to build them.

Conventions

ThingConvention
Audio±1.0. Multiply by 5 for Rack's ±5 V.
FrequencyHz. Convert Rack pitch voltage with ml::voltToHz().
Other parameters0..1 unless the component says otherwise. Times are in seconds.
Setupinit(sampleRate) resets state and sizes buffers. Safe to call again whenever the rate changes.
Processingprocess() returns one sample. Stereo components take float& left, float& right.
Triggerstrigger(), or a bool argument to process().
PolyphonyOne voice per instance. For 16 channels, hold an array of 16.
ThreadsNone. Nothing allocates outside init().

Design

The original firmware runs at fixed sample rates (from 31.25 kHz to 96 kHz), processes audio in blocks and depends on stmlib. In this library:

  • Every component works at any sample rate. Constants that assumed one rate are recomputed in init().
  • Processing is per sample. Components that are costly to update (such as a 64-mode resonator) recompute their coefficients every few samples internally, as the originals did per block.
  • The only dependency is the C++11 standard library. There is no stmlib and no Rack header, so every component can be tested outside Rack.
  • All maths is float. The fixed-point code from the older modules is ported to float.
