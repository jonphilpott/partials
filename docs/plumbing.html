Plumbing

Filters, delays and helpers the other components are built from. They are all useful on their own.

Svf

#include "pt/filter/svf.h" · from stmlib

A state-variable filter: one 12 dB/octave filter that gives low-pass, band-pass and high-pass at the same time. Gillet uses it everywhere: as a synth filter, for each mode of the modal resonator, as formant filters and in the drums.

How it works. Two integrators sit in a feedback loop. This is the "zero-delay feedback" version: it solves the loop for the current sample, rather than using the previous one, so the filter stays in tune right up to Nyquist and its settings can change on every sample without clicks or instability.

CallEffect
init(sampleRate)Set the rate and clear the state.
reset()Clear the state (silence a ringing filter).
setFrequency(hz, q)Cutoff and resonance. Q of 0.5 gives no peak, 0.707 is flat (Butterworth), 2–5 is a resonant synth filter, 10 and above ring like a bell.
process(in)Returns pt::SvfOut with fields lp, bp and hp. Outputs you don't use cost nothing.
r()1/q. bp * r() is a band-pass whose peak stays at unity gain whatever the Q.
setCoefficients(f, q, approx)Low-level: f is cutoff / sample rate, and approx is a pt::TanApprox (see below).
setGQ(g, q), g()Set or read the pre-computed frequency coefficient, for example to copy tuning from one filter to another.
pt::Svf filter;
// onSampleRateChange: filter.init(e.sampleRate);

void process(const ProcessArgs& args) override {
    float cutoff = pt::voltToHz(params[CUTOFF].getValue() + inputs[CUTOFF_CV].getVoltage());
    float q = 0.5f + 20.f * params[RESONANCE].getValue();
    filter.setFrequency(pt::clamp(cutoff, 20.f, 20000.f), q);

    pt::SvfOut o = filter.process(inputs[IN].getVoltage() / 5.f);
    outputs[LP].setVoltage(5.f * o.lp);
    outputs[BP].setVoltage(5.f * o.bp);
    outputs[HP].setVoltage(5.f * o.hp);
    outputs[NOTCH].setVoltage(5.f * (o.lp + o.hp));   // notch = LP + HP
}

tanApprox(f, approx): the filter needs tan(π·f). Gillet's code uses cheap polynomial versions of it, and ports keep the same one so they sound identical. Options:

  • Exact: std::tan, used by setFrequency.
  • Accurate: good everywhere.
  • Fast: good from 16 Hz to 16 kHz at 48 kHz.
  • Dirty: good below about 8 kHz.
// A bank of 32 filters retuned every sample: the cheap approximation is plenty
float f = hz * args.sampleTime;   // cutoff / sample rate
bank[i].setCoefficients(f, 50.f, pt::TanApprox::Fast);

OnePole

#include "pt/filter/one_pole.h" · from stmlib

The simplest filter: a gentle 6 dB/octave low-pass and high-pass. Use it to tame harsh highs, take the edge off a square wave, remove rumble, or smooth a CV with a cutoff in Hz. It is built the same way as the Svf, so it stays accurate up to Nyquist.

CallEffect
init(sampleRate), reset()As for Svf.
setFrequency(hz)Cutoff: the −3 dB point.
process(in)Returns pt::OnePoleOut with fields lp and hp.
setCoefficients(f, approx)Low-level: cutoff / sample rate, plus a TanApprox.
pt::OnePole tone;
// onSampleRateChange: tone.init(e.sampleRate);

// A tilt "tone" knob: below the middle darkens (low-pass), above thins (high-pass)
tone.setFrequency(800.f);
pt::OnePoleOut o = tone.process(in);
float t = params[TONE].getValue();          // 0..1, 0.5 = flat
float out = t < 0.5f ? pt::crossfade(o.lp, in, t * 2.f)
                     : pt::crossfade(in, o.hp, t * 2.f - 1.f);

DcBlocker

#include "pt/filter/dc_blocker.h" · from stmlib

Removes DC offset and slow drift: a one-pole high-pass with a very low cutoff. Resonators, feedback loops and asymmetric distortion can all build up DC, which wastes headroom and makes clicks when a downstream VCA opens. Put one before the output.

CallEffect
init(sampleRate, cutoffHz = 10)5–20 Hz is typical.
reset()Clear the state.
process(in)Returns the input minus its DC.
pt::DcBlocker dc;
// onSampleRateChange: dc.init(e.sampleRate, 10.f);

// Half-wave rectified distortion is lopsided, so its output carries DC
float y = in > 0.f ? in : 0.2f * in;
outputs[OUT].setVoltage(5.f * dc.process(y));

DelayLine

#include "pt/fx/delay_line.h" · from stmlib

A circular buffer: write one sample at a time, read back from any point in the past. It is the basic part of echoes, choruses, comb filters, strings and reverbs.

Memory. init(maxDelaySamples) allocates the buffer, so call it from onSampleRateChange, never from process. Size it from the sample rate so delay times hold in seconds.

CallEffect
init(maxDelay)Allocate room for up to maxDelay samples. The buffer is rounded up to a power of two.
reset()Clear to silence.
write(x)Push one sample.
read(size_t n)The sample written n writes ago; read(1) is the latest.
read(float d)Fractional delay, linear interpolation. Cheap, slightly dull.
readHermite(float d)Fractional delay, cubic interpolation. Brighter; use it for tuned delays and modulated delays.
allpass(in, n, g)An all-pass filter on the line. It passes every frequency at the same level but smears them in time, which is the basic part of reverb diffusion.
pt::DelayLine line;

void onSampleRateChange(const SampleRateChangeEvent& e) override {
    line.init(size_t(e.sampleRate * 2.f));     // up to 2 seconds
}

void process(const ProcessArgs& args) override {
    float in = inputs[IN].getVoltage() / 5.f;
    float time = 0.01f + 1.99f * params[TIME].getValue();      // seconds
    float echo = line.readHermite(time * args.sampleRate);
    line.write(in + params[FEEDBACK].getValue() * echo);
    outputs[OUT].setVoltage(5.f * (in + echo));
}
// A feedback comb filter tuned to a pitch: metallic, Karplus-Strong-like
float period = args.sampleRate / pt::voltToHz(inputs[VOCT].getVoltage());
float y = in + 0.95f * comb.readHermite(period);
comb.write(y);

Sine oscillators

#include "pt/osc/sine.h" · SineOscillator from Plaits, CosineOscillator from stmlib

sineFromPhase(phase) and SineOscillator

A table-based sine: cheaper than std::sin and accurate to about −100 dB. sineFromPhase(p) turns a 0..1 phase into a sine; only the fractional part of the phase counts. SineOscillator is a plain sine oscillator built on it, for LFOs, test tones and FM.

CallEffect
init(sampleRate), reset()Set the rate; reset restarts the phase at 0.
setFrequency(hz), process()Next sample, ±1.
next(f), next(f, amplitude, sine, cosine)Low-level: f is Hz / sample rate; the second form gives sine and cosine together.
pt::SineOscillator lfo;   // onSampleRateChange: lfo.init(e.sampleRate);

lfo.setFrequency(0.1f + 10.f * params[RATE].getValue());   // 0.1 to 10 Hz
outputs[LFO_OUT].setVoltage(5.f * lfo.process());

// Two-operator FM with sineFromPhase: the modulator shifts the carrier's phase
modPhase += hz * 2.f * args.sampleTime;
carPhase += hz * args.sampleTime;
float mod = pt::sineFromPhase(modPhase);
float out = pt::sineFromPhase(carPhase + params[INDEX].getValue() * mod);

CosineOscillator

Produces the series 0.5 + 0.5·cos(n·w) for n = 0, 1, 2… at a cost of one multiply per value, using the recurrence cos((n+1)w) = 2cos(w)·cos(nw) − cos((n−1)w). It is rarely a free-running audio oscillator. Its main use is computing a set of per-harmonic gains cheaply: harmonic k weighted by 0.5 + 0.5·cos(2πk·position) is how a pickup or strike point shapes a spectrum.

CallEffect
init(f)Set w = 2π·f, where f is in cycles per step, and rewind.
initApproximate(f)The same with a cheaper, slightly less accurate cos(); the original code uses it.
start()Rewind to n = 0.
next(), value()The next value (0..1); the latest value again.
// Additive voice: 16 harmonics with a "pickup position" spectral comb
pt::CosineOscillator gains;
gains.init(params[POSITION].getValue());   // recompute once per sample
float sum = 0.f;
for (int k = 0; k < 16; ++k) {
    sum += harmonic[k] * gains.next();       // harmonic[k]: your partials
}

BasicOscillator

#include "pt/osc/basic.h" · from Plaits

Plaits' alias-free oscillator, with saw, triangle, variable-symmetry slope, pulse with variable width, filtered squares and an impulse train. It uses the PolyBLEP trick to remove aliasing, at the cost of one sample of latency. Rack already has good VCOs, so this is mainly plumbing for other components (the ring-mod hi-hat, wavefolder inputs), but it works well as a simple oscillator.

It differs from Plaits in two ways: the dark square is scaled to about ±1 like the other shapes, and the start-up state is set from the shape, which removes a first-sample spike on SLOPE and IMPULSE_TRAIN.

CallEffect
init(sampleRate)Resets.
setShape(s)SAW, TRIANGLE, SLOPE (triangle with variable symmetry), SQUARE, SQUARE_BRIGHT (thin, nasal), SQUARE_DARK (soft, hollow), SQUARE_TRIANGLE (smooth), IMPULSE_TRAIN.
setFrequency(hz)Up to a quarter of the sample rate.
setPulseWidth(x)0..1: the width for squares, the symmetry for SLOPE.
process()Next sample, about ±1.
process(f, pw)Low-level: f is Hz / sample rate.
pt::BasicOscillator osc;   // onSampleRateChange: osc.init(e.sampleRate);

// A simple VCO: shape switch, PWM input
osc.setShape(static_cast<pt::BasicOscillator::Shape>(int(params[SHAPE].getValue())));
osc.setFrequency(pt::voltToHz(inputs[VOCT].getVoltage()));
osc.setPulseWidth(pt::clamp(0.5f + inputs[PWM].getVoltage() / 10.f, 0.05f, 0.95f));
outputs[OUT].setVoltage(5.f * osc.process());

PolyBLEP

#include "pt/osc/polyblep.h" · from stmlib

Four small functions that remove aliasing from sudden jumps: the edges of saw and square waves, hard sync, sample and hold. The Decimator uses them, and the oscillators will.

Why it's needed. A jump that falls between two samples gets rounded to the nearest one. The rounding error contains frequencies above Nyquist, which fold back down as the inharmonic whine of a naive digital oscillator.

How it works. If you know where the jump really happened (a fraction t of a sample ago, 0..1) and its size, a two-sample correction approximates a band-limited step ("BLEP"). Add thisBlepSample(t) × the jump to the current sample and nextBlepSample(t) × the jump to the next one; this means delaying the output by one sample. The Integrated versions correct a sudden change of slope (a corner, as in a triangle wave) instead of value.

FunctionUse
thisBlepSample(t), nextBlepSample(t)Correct a step in value (saw reset, square edge).
thisIntegratedBlepSample(t), nextIntegratedBlepSample(t)Correct a step in slope (triangle corner).
// An alias-free sawtooth: the naive ramp plus a BLEP at each reset
float phase = 0.f, next = 0.f;   // members

float sawProcess(float hz, float sampleTime) {
    float inc = hz * sampleTime;
    float out = next;                          // one sample of latency
    next = 0.f;
    phase += inc;
    if (phase >= 1.f) {
        phase -= 1.f;
        float t = phase / inc;                 // how far past the reset we are
        out -= pt::thisBlepSample(t);          // the ramp drops by 1: jump = -1
        next -= pt::nextBlepSample(t);
    }
    next += phase;                             // the naive ramp, delayed
    return 2.f * out - 1.f;                    // 0..1 to ±1
}
