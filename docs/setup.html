Getting started

Set up a VCV Rack plugin build environment, build and install the example modules, then use the library in your own plugin.

The steps:

  1. Install a compiler and build tools.
  2. Download the Rack SDK.
  3. Build and install the examples.
  4. Start your own plugin.

The library itself needs nothing beyond a C++11 compiler; the toolchain and SDK are what Rack plugins need. These instructions follow the official VCV Rack build guide; check there if anything has changed.

1. Install the build tools

macOS

  1. Install Apple's command-line tools, which include the compiler: 
    xcode-select --install
  2. Install Homebrew, then the tools Rack's build system uses: 
    brew install git wget cmake autoconf automake libtool jq python zstd pkg-config

Windows

Rack plugins are built with MinGW, using the MSYS2 environment.

  1. Install MSYS2.
  2. Open the MinGW 64-bit shell from the Start menu. Not the default MSYS shell: it has the wrong compiler.
  3. Update the package database: 
    pacman -Syu
  4. Close and reopen the MinGW 64-bit shell, then install the tools: 
    pacman -Syu git wget make tar unzip zip mingw-w64-x86_64-gcc mingw-w64-x86_64-gdb mingw-w64-x86_64-cmake autoconf automake libtool mingw-w64-x86_64-jq python zstd mingw-w64-x86_64-pkgconf

If builds are very slow or fail with permission errors, try pausing your antivirus.

Linux (Ubuntu, Debian)

sudo apt install unzip git gdb curl cmake libx11-dev libglu1-mesa-dev libxrandr-dev libxinerama-dev libxcursor-dev libxi-dev zlib1g-dev libasound2-dev libgtk2.0-dev libgtk-3-dev libjack-jackd2-dev jq zstd libpulse-dev pkg-config autoconf libtool

Linux (Arch)

pacman -S git wget gcc gdb make cmake tar unzip zip curl jq python zstd libpulse pkgconf

2. Download the Rack SDK

The SDK holds Rack's headers, its library to link against, and the shared Makefile (plugin.mk) that every plugin uses. Download the one for your computer from vcvrack.com/downloads, or with one of these commands (replace 2.6.4 with the latest version):

ComputerDownload
Mac, Apple Silicon (M1 and later)https://vcvrack.com/downloads/Rack-SDK-2.6.4-mac-arm64.zip
Mac, Intelhttps://vcvrack.com/downloads/Rack-SDK-2.6.4-mac-x64.zip
Windowshttps://vcvrack.com/downloads/Rack-SDK-2.6.4-win-x64.zip
Linuxhttps://vcvrack.com/downloads/Rack-SDK-2.6.4-lin-x64.zip

Unzip it anywhere and tell the build where it is with the RACK_DIR environment variable:

cd ~/git
curl -LO https://vcvrack.com/downloads/Rack-SDK-2.6.4-mac-arm64.zip
unzip Rack-SDK-2.6.4-mac-arm64.zip           # creates ~/git/Rack-SDK
export RACK_DIR=~/git/Rack-SDK

Add the export line to your ~/.zshrc (macOS) or ~/.bashrc (Linux and MSYS2) so it is set in every new shell.

Use an SDK version no newer than the Rack you run: plugins built with SDK 2.6 need Rack 2.6 or later. Rack 2 plugins don't load in Rack 1, and vice versa.

3. Build and install the examples

The examples/rack-plugin folder is a complete Rack plugin with six demo modules, one per library area:

ModuleBuilt from
StrikePlucker → ModalResonator → LowPassGate
HazeOverdrive → Ensemble → Diffuser → Reverb → Limiter
KitAnalogKick, AnalogSnare, HiHat
DriftClockToRamp, RandomSequence, Lag, Quantizer, Slope
PaletteSix oscillators behind one set of controls
BridgeXmod, Hilbert frequency shifter, Vocoder

From the repository's root:

cd examples/rack-plugin
make             # build plugin.dylib / plugin.dll / plugin.so
make install     # build, package and install into Rack's user folder

Restart Rack. The modules appear in the module browser under the brand partials.

make install copies the packaged plugin into the plugins-<os>-<cpu> folder inside Rack's user folder. Rack unpacks it on its next start. Rack can open the user folder for you from Help → Open user folder.

SystemPlugins folder
macOS~/Library/Application Support/Rack2/plugins-mac-arm64 (or -mac-x64)
Windows%LOCALAPPDATA%\Rack2\plugins-win-x64
Linux~/.local/share/Rack2/plugins-lin-x64 (or under $XDG_DATA_HOME)

Other useful targets:

make cleanRemoves build files.
make -j8Compiles 8 files at once.

examples/tutorial-plugin holds the finished module from the tutorial, and builds the same way.

The example's Makefile points at the library with a relative path (FLAGS += -I../../include). If you move the example elsewhere, change that path to wherever partials/include lives.

If it doesn't build

  • "No rule to make target …/plugin.mk": RACK_DIR isn't set, or points at the wrong folder. ls $RACK_DIR/plugin.mk should list the file. You can also pass it directly: make RACK_DIR=~/git/Rack-SDK.
  • "pt/…h: No such file": the include path in the Makefile doesn't reach partials/include.
  • On Windows, compiler or linker not found: you are in the MSYS shell rather than the MinGW 64-bit shell.
  • The module doesn't appear in Rack: check Rack's log (log.txt in the user folder). An "incompatible" message means the SDK is newer than your Rack.

4. Use the library in your own plugin

The tutorial walks through these steps in detail, building a complete module. In short:

  1. Create a plugin skeleton with the SDK's helper, answering its questions: 
    cd ~/git
$RACK_DIR/helper.py createplugin MyPlugin
cd MyPlugin
  2. Draw a panel (an SVG in res/) and generate a module from it: 
    $RACK_DIR/helper.py createmodule MyModule res/MyModule.svg src/MyModule.cpp
  3. Point the plugin's Makefile at partials by adding one line before include $(RACK_DIR)/plugin.mk. The library is header-only, so there is nothing else to build or link. 
    # Makefile
FLAGS += -I../partials/include
  4. Include components and use them. The overview shows the pattern every component follows: 
    #include "plugin.hpp"
#include "pt/physical/string.h"

struct MyModule : Module {
    pt::String string;

    void onSampleRateChange(const SampleRateChangeEvent& e) override {
        string.init(e.sampleRate);
    }

    void process(const ProcessArgs& args) override {
        string.setFrequency(pt::voltToHz(inputs[VOCT_INPUT].getVoltage()));
        outputs[OUT_OUTPUT].setVoltage(5.f * string.process(inputs[IN_INPUT].getVoltage() / 5.f));
    }
};
  5. Build and install with make install, as for the examples.

Instead of a relative path, you can keep partials inside your plugin's repository, for example as a git submodule:

git submodule add <partials repository URL> dep/partials
# Makefile
FLAGS += -Idep/partials/include

If you publish a plugin, keep the library's LICENSE file with it: it is MIT-licensed, and the notice credits Emilie Gillet, whose code it is derived from.

5. Run the library's tests (optional)

The tests need only a C++ compiler; Rack and the SDK aren't involved.

cd tests
make check

This builds and runs every test program and checks that the docs cover every component. Most tests also write WAV files into tests/build/ for listening.

The golden tests in tests/golden compile Gillet's original code next to the library and compare their outputs. They need her eurorack repository and its stmlib submodule:

git clone https://github.com/pichenettes/eurorack.git ~/git/eurorack
cd ~/git/eurorack
git submodule update --init stmlib

cd /path/to/partials/tests/golden
make check EURORACK=~/git/eurorack
