Tutorial: your first module

Build a VCV Rack module from scratch with mutablelib: a sawtooth oscillator into a low-pass filter, with knobs for the oscillator's frequency and the filter's cutoff.

By the end you will have a working module in Rack and know the pattern every mutablelib module follows. It takes about 20 minutes. The finished plugin is in examples/tutorial-plugin if you want to compare.

Before you start: install the build tools and the Rack SDK, and set RACK_DIR, as described in Getting started (steps 1 and 2). Check with:

ls $RACK_DIR/helper.py

The plan

  [FREQUENCY knob]          [CUTOFF knob]
         |                        |
         v                        v
   BasicOscillator  ------->    Svf      ------->  OUT jack
   (sawtooth)             (low-pass)

Two mutablelib components do the work:

  • ml::BasicOscillator: an alias-free sawtooth.
  • ml::Svf: a state-variable filter, used here as a low-pass.

Our code reads the knobs, passes their values to the components, and sends the result to the output, once per sample.

Step 1: create the plugin

A Rack plugin is a package of one or more modules. The SDK's helper script creates an empty one. From the folder where you keep your projects:

$RACK_DIR/helper.py createplugin MyFirstPlugin

It asks a few questions. Press Enter to accept a default:

Plugin name [MyFirstPlugin]: My First Plugin
Version [2.0.0]:
License (if open-source, use license identifier from https://spdx.org/licenses/) [proprietary]: MIT
Brand (prefix for all module names) [My First Plugin]: MyBrand
Author []: Your Name
...                          (the rest are optional: press Enter)

This creates a MyFirstPlugin folder:

MyFirstPlugin/
  Makefile        how to build the plugin
  plugin.json     the plugin's name, version and list of modules
  res/            panels and other resources
  src/
    plugin.hpp    declarations shared by all modules
    plugin.cpp    registers the modules with Rack

Step 2: add mutablelib

mutablelib is header-only, so the plugin only needs to know where its include folder is. Put a copy of the library inside the plugin, in a dep (dependencies) folder:

cd MyFirstPlugin
mkdir dep
cp -r /path/to/mutablelib dep/mutablelib
# or, if your plugin is a git repository, add it as a submodule:
# git submodule add <mutablelib repository URL> dep/mutablelib

Then open Makefile and change the empty FLAGS += line to:

# mutablelib is header-only: adding its include folder is all it needs.
FLAGS += -Idep/mutablelib/include

-I adds a folder to the compiler's search path, so #include "ml/osc/basic.h" finds dep/mutablelib/include/ml/osc/basic.h. There's nothing to compile or link separately.

Step 3: draw the panel

A module's panel is an SVG image. It also tells the helper where the knobs and jacks go. Any shape inside a layer called components marks a control, by its colour:

ColourBecomes
red #ff0000a knob or switch (a param)
green #00ff00an input jack
blue #0000ffan output jack
magenta #ff00ffa light

The shape's id becomes the control's name in the code. Save this as res/SawFilter.svg:

<svg xmlns="http://www.w3.org/2000/svg" xmlns:inkscape="http://www.inkscape.org/namespaces/inkscape"
     width="30.48mm" height="128.5mm" viewBox="0 0 30.48 128.5">
  <!-- The panel: 6 HP wide (6 x 5.08 mm) and 128.5 mm tall, the Eurorack size. -->
  <rect width="30.48" height="128.5" fill="#e6e4dc"/>
  <rect width="30.48" height="12" fill="#2b2b2b"/>
  <rect x="4" y="98" width="22.48" height="20" rx="2" fill="#2b2b2b"/>

  <!-- Where the knobs and jack go. Rack's helper reads this layer to write
       the C++ code; it is hidden, so Rack doesn't draw it.
       Red = knob (param), green = input, blue = output. -->
  <g id="components" inkscape:label="components" inkscape:groupmode="layer" style="display:none">
    <circle id="FREQ" cx="15.24" cy="38" r="4" fill="#ff0000"/>
    <circle id="CUTOFF" cx="15.24" cy="68" r="4" fill="#ff0000"/>
    <circle id="OUT" cx="15.24" cy="108" r="4" fill="#0000ff"/>
  </g>
</svg>

Panel widths are multiples of 5.08 mm (one "HP"); this one is 6 HP. The components layer is hidden (display:none) so Rack draws the real knobs on top, not the coloured circles.

Rack can't draw SVG <text>. To label the knobs, draw the labels as shapes, or in Inkscape write them as text and use Path → Object to Path before saving. This tutorial skips labels.

Step 4: generate the module

The helper reads the panel and writes a module source file:

$RACK_DIR/helper.py createmodule SawFilter res/SawFilter.svg src/SawFilter.cpp

It asks for a name, description and tags (for example Saw Filter, a one-line description, and Oscillator, Filter), adds the module to plugin.json, and reports what it found:

Found 2 params, 0 inputs, 1 outputs, 0 lights, and 0 custom widgets in "components" layer.

To enable the module, add

	extern Model* modelSawFilter;

to plugin.hpp, and add

	p->addModel(modelSawFilter);

to the init() function in plugin.cpp.
Source file generated at src/SawFilter.cpp

Do what it says. In src/plugin.hpp, add the declaration at the end:

extern Model* modelSawFilter;

In src/plugin.cpp, inside init():

p->addModel(modelSawFilter);

The generated src/SawFilter.cpp already compiles: it has the panel, two knobs and the jack, but makes no sound. It contains two parts:

  • struct SawFilter : Module is the sound engine. Its enums give each control a number: FREQ_PARAM and CUTOFF_PARAM come from the panel ids. process() is where the audio happens.
  • struct SawFilterWidget : ModuleWidget is what you see: the panel, screws, knobs and jack, placed where the panel's circles were.

Step 5: write the sound

Now fill in the module. The changes are all inside struct SawFilter; the widget stays as generated.

5a. Include the components

At the top of src/SawFilter.cpp, after #include "plugin.hpp":

#include "ml/core/units.h"    // voltToHz(), kFreqC4
#include "ml/filter/svf.h"     // ml::Svf
#include "ml/osc/basic.h"      // ml::BasicOscillator

5b. Add them as members

Inside struct SawFilter, after the enums. They are ordinary member variables: no new, no pointers.

	ml::BasicOscillator oscillator;
	ml::Svf filter;

5c. Configure the knobs

Replace the two generated configParam lines in the constructor. Their arguments are: control, minimum, maximum, default, name, unit, then two numbers for how Rack displays the value (multiplier × basevalue), so the tooltip shows Hz:

	SawFilter() {
		config(PARAMS_LEN, INPUTS_LEN, OUTPUTS_LEN, LIGHTS_LEN);
		// Frequency knob: -4..+4 octaves around C4. Rack shows it in Hz:
		// 261.63 * 2^value, from 16 Hz to 4186 Hz.
		configParam(FREQ_PARAM, -4.f, 4.f, 0.f, "Frequency", " Hz", 2.f, ml::kFreqC4);
		// Cutoff knob: 0..1 mapped exponentially to 20 Hz..20 kHz. Rack
		// shows it in Hz: 20 * 1000^value.
		configParam(CUTOFF_PARAM, 0.f, 1.f, 0.5f, "Cutoff", " Hz", 1000.f, 20.f);
		configOutput(OUT_OUTPUT, "Audio");

		oscillator.setShape(ml::BasicOscillator::SAW);
	}

Both knobs are exponential: each step multiplies the frequency rather than adding to it. That matches how we hear pitch, where every octave sounds the same size, so the knobs feel even across their range.

5d. Initialise at the right sample rate

Every mutablelib component needs init(sampleRate) before use. Rack tells a module the sample rate through onSampleRateChange. It is called when the module is added and whenever you change the engine's sample rate, so it is the one place you need. Add it to struct SawFilter:

	// Called when the module is added and whenever the sample rate
	// changes: the place to (re)initialise DSP components.
	void onSampleRateChange(const SampleRateChangeEvent& e) override {
		oscillator.init(e.sampleRate);
		filter.init(e.sampleRate);
	}

5e. Process each sample

Replace the empty process(). Rack calls it once per sample, 48,000 times a second at 48 kHz:

	// Called once per sample.
	void process(const ProcessArgs& args) override {
		// 1. Read the knobs and convert them to Hz.
		float frequency = ml::voltToHz(params[FREQ_PARAM].getValue());
		float cutoff = 20.f * std::pow(1000.f, params[CUTOFF_PARAM].getValue());

		// 2. Oscillator: one sample of an alias-free sawtooth, about +-1.
		oscillator.setFrequency(frequency);
		float saw = oscillator.process();

		// 3. Filter: the saw through a 12 dB/octave low-pass. Q 1.0 adds a
		// little resonance at the cutoff.
		filter.setFrequency(cutoff, 1.f);
		float filtered = filter.process(saw).lp;

		// 4. Rack's audio level is +-5 V.
		outputs[OUT_OUTPUT].setVoltage(5.f * filtered);
	}

Line by line:

  • Units. mutablelib works in Hz and ±1; Rack works in volts. ml::voltToHz() turns the frequency knob's octaves into Hz (0 is C4, 261.63 Hz, and each +1 doubles it). The cutoff uses the same formula as its display.
  • Setters, then process(). Every component works this way: set the parameters, then call process() once per sample. Setting them every sample is fine and keeps the knobs responsive.
  • filter.process(saw) returns all three outputs of the state-variable filter at once; .lp picks the low-pass. Try .bp (band-pass) or .hp (high-pass).
  • Scaling. The final 5.f * converts the library's ±1 to Rack's ±5 V audio standard.

The complete file is in examples/tutorial-plugin/src/SawFilter.cpp.

Step 6: build, install and play

make install

This compiles the plugin, packages it and copies it into Rack's plugins folder. Then:

  1. Restart Rack.
  2. Right-click the rack, search for Saw Filter (brand MyBrand) and add it.
  3. Patch OUT into an Audio module (or a mixer into one), and set the volume low first: a raw sawtooth is loud.
  4. Turn FREQUENCY to change the pitch, and CUTOFF to sweep from a muffled hum (cutoff below the pitch) to a bright buzz (cutoff well above it). Hover over a knob to see its value in Hz.

After changing the code, run make install again and restart Rack. If something doesn't build, see If it doesn't build in Getting started.

Next steps

Each of these is a few lines, and each uses the same pattern: add a control to the panel's components layer, regenerate or edit the code, then read it in process().

  • A V/Oct input. Add a green circle with id VOCT, then add the input voltage to the knob before converting, so the module plays in tune from a sequencer: 
    float frequency = ml::voltToHz(params[FREQ_PARAM].getValue() + inputs[VOCT_INPUT].getVoltage());
  • A resonance knob. Add a red circle with id RES, configured 0..1, and map it to Q: 
    filter.setFrequency(cutoff, 0.5f + 15.f * params[RES_PARAM].getValue());
  • Cutoff CV. Treat a 0..10 V input as an extra 0..1 on the knob: 
    float k = ml::clamp(params[CUTOFF_PARAM].getValue() + inputs[CUTOFF_INPUT].getVoltage() / 10.f, 0.f, 1.f);
float cutoff = 20.f * std::pow(1000.f, k);
  • Other waveforms. setShape(ml::BasicOscillator::SQUARE), or swap in a more unusual oscillator from the Oscillators page.
  • An envelope. Add a gate input and an ml::LowPassGate after the filter, and you have a complete voice.

The example modules in examples/rack-plugin use the same pattern at a larger scale, combining several components each.
